## 1. Context

P3's parent design (approved 2026-05-19) split frame interpolation into 4
sub-pillars. **P3.1 is the foundation** — purely the abstraction layer that
later sub-pillars consume:

- **P3.2** ships `RIFEFilter` + bundled `rife-ncnn-vulkan.exe` + the side-task
  loop that batches frames through the binary. Returns a real `PipelineSpec`
  from `pipeline_spec()`.
- **P3.3** extends `_ProcessSlot` from "1 Popen" to "1 primary + N side procs
  + 1 side task thread" so the Transcoder can spawn the RIFE pipeline.
- **P3.4** wires the popup toggle through `nm_host` → proxy → transcoder,
  adds the `enable_smooth` gate + `license.is_pro()` stub + demote-on-failure.

P3.1 lands three small, independently-testable pieces — none of which change
runtime behavior for existing casts:

1. **`PipelineSpec` + `SideTaskContext` frozen dataclasses** in a new module.
   The shape RIFEFilter will produce in P3.2 and `_ProcessSlot` will consume
   in P3.3. Defined now so the contract is in source for both sides.
2. **`FilterStage.pipeline_spec()` Protocol method**, returning `None` for
   `NoopFilter` and `SubtitleBurnIn` (today's only filters). Pure -vf filters
   stay pure -vf filters; the seam exists for filters that need their own
   process topology.
3. **`probe_input_video()`** in `ffmpeg_probe.py`. Returns width / height /
   pix_fmt + CFR-only fps via `ffprobe -show_streams -select_streams v:0 -of
   json`. P3.4 will call this from `_handle_cast` to decide whether to skip
   interpolation (VFR / unknown / source already ≥ target_fps).

Existing 185-test baseline stays green. ~15 new tests cover the new surface.
Boot smoke (`python -m castbooster`) unchanged. No regression in the proxy:
`_handle_cast` still constructs `FilterChain([NoopFilter()])` — NoopFilter's
`pipeline_spec()` returns `None`, which the (future P3.3) Transcoder treats
as "single-Popen path, today's behavior".

## 2. Decisions

Parent-spec decisions inherited verbatim (D1–D9 of the P3 spec). P3.1-specific
decisions locked this brainstorm (2026-05-19):

| # | Decision | Choice | Why |
|---|---|---|---|
| P3.1-A | Protocol method shape | **Required `pipeline_spec()` on FilterStage** | NoopFilter, SubtitleBurnIn, and the FakeScaleFilter test fixture each get an explicit method returning `None`. Signals that every filter declares its pipeline shape — RIFE is the only one returning a real spec; everyone else is explicit about being a pure -vf filter. Confirmed with user via AskUserQuestion 2026-05-19. |
| P3.1-B | ffprobe binary location | **Derived from `AccelProfile.ffmpeg_path`** — same parent dir, basename `ffprobe.exe` on Windows / `ffprobe` elsewhere. | Bundled Gyan zip ships both side-by-side; verified `app/castbooster/bin/ffprobe.exe` exists. No `CASTBOOSTER_FFPROBE` env var — overcomplicated for v1. |
| P3.1-C | VFR semantics (incl. `avg_frame_rate == "0/0"`) | **`fps = parse(r_frame_rate)` iff `r_frame_rate == avg_frame_rate`, else `None`** | Naturally covers HLS-with-unknown-duration (where `avg_frame_rate == "0/0"`) → treated as VFR → fps=None → interp skipped → passthrough cast. Standard ffprobe-based CFR detection. |
| P3.1-D | "No video stream" handling | **Return `None`** (probe-failed semantic) | After `-select_streams v:0`, a successful probe on an audio-only input returns `{"streams": []}`. From a *video* probe's POV that's indistinguishable from probe failure — caller's NoopFilter fallback applies either way. Simpler than a special return value. |
| P3.1-E | ffprobe timeout | **10.0s** | Existing `_PROBE_TIMEOUT = 5.0s` is for local 1-frame encode tests. Video probes hit the network (HLS manifest fetch) — give it more headroom. Caller treats timeout as probe failure → `None` → passthrough cast. |
| P3.1-F | Branch strategy | **`pillar-3.1/pipeline-abstraction` cut from master, merged via `--no-ff` after review** | Overrides the "master-only" default from vault context.md per user's explicit instruction in kickoff prompt. Aligns with how P2.4 (`pillar-2.4/proxy-integration`) was handled. |

## 3. Architecture

### 3.1 New module: `app/castbooster/pipeline_spec.py`

```python
"""Pipeline specs for FilterStages that need their own process topology.

P3.1 ships the dataclasses only. Consumed in P3.3 by _ProcessSlot.
Produced in P3.2 by RIFEFilter.
"""
from __future__ import annotations

import threading
from dataclasses import dataclass
from pathlib import Path
from typing import IO, Callable


@dataclass(frozen=True)
class SideTaskContext:
    """Handle passed to a FilterStage's side-task callable at spawn time.

    The side task runs synchronously on its own threading.Thread (spawned
    by _ProcessSlot in P3.3) and must check `cancel_event` in its inner
    loop. Writing to `encoder_stdin` feeds the encode ffmpeg directly.
    """
    input_url: str
    target_fps: int
    encoder_stdin: IO[bytes]
    workdir: Path
    cancel_event: threading.Event


@dataclass(frozen=True)
class PipelineSpec:
    """What a non-trivial FilterStage tells the Transcoder about its pipeline.

    A return value of `None` from FilterStage.pipeline_spec() means "pure -vf
    filter, today's single-Popen behavior". A real PipelineSpec triggers the
    multi-process path in P3.3.

    Fields:
        encoder_input_format: how to configure the encode ffmpeg's stdin.
            Format string: "rawvideo:<pix_fmt>:<W>x<H>", e.g.
            "rawvideo:yuv420p:1920x1080".
        target_fps: output framerate. Encoder gets -r and a sqrt-scaled
            bitrate (per parent spec D6, implemented in P3.3).
        side_task_factory: synchronous callable invoked on a fresh thread
            with a SideTaskContext. Raises on subprocess failure so
            _ProcessSlot can mark the slot FAILED.
    """
    encoder_input_format: str
    target_fps: int
    side_task_factory: Callable[[SideTaskContext], None]
```

Both dataclasses are frozen (immutable). `Callable` is the standard typing
import — at runtime the field just holds a function reference.

## 4. Reference implementation — `probe_input_video`

```python
def probe_input_video(
    url: str,
    ffmpeg_path: Optional[str] = None,
) -> Optional[InputVideoInfo]:
    if ffmpeg_path is None:
        ffmpeg_path = detect().ffmpeg_path
    ffprobe = _locate_ffprobe(ffmpeg_path)
    if ffprobe is None:
        log.warning("ffprobe not found next to %s", ffmpeg_path)
        return None
    args = [
        ffprobe, "-hide_banner", "-loglevel", "error",
        "-show_streams", "-select_streams", "v:0",
        "-of", "json", url,
    ]
    try:
        result = _run(args, timeout=_VIDEO_PROBE_TIMEOUT)
    except subprocess.TimeoutExpired:
        log.warning("ffprobe timed out on %s", url)
        return None
    except Exception:
        log.exception("ffprobe crashed on %s", url)
        return None
    if result.returncode != 0:
        log.warning("ffprobe failed (exit=%d) on %s: %s",
                    result.returncode, url, (result.stderr or "")[:200])
        return None
    try:
        data = json.loads(result.stdout or "{}")
    except ValueError:
        log.warning("ffprobe returned malformed JSON on %s", url)
        return None
    streams = data.get("streams") or []
    if not streams:
        return None
    s = streams[0]
    try:
        width = int(s["width"])
        height = int(s["height"])
        pix_fmt = str(s["pix_fmt"])
    except (KeyError, ValueError, TypeError):
        return None
    r = s.get("r_frame_rate") or ""
    a = s.get("avg_frame_rate") or ""
    fps = _parse_rational_fps(r) if r and r == a else None
    return InputVideoInfo(fps=fps, width=width, height=height, pix_fmt=pix_fmt)
```

## 9. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Protocol change breaks any third-party FilterStage implementation | None today (`grep -r FilterStage` finds only `NoopFilter`, `SubtitleBurnIn`, and the test FakeScaleFilter — all three are owned by us and updated in this sub-pillar). Documented as a deliberate Protocol extension. |
| `_parse_rational_fps` mishandles a fraction we haven't anticipated | V12 covers `"24000/1001"`, `"0/0"`, `""`, `"abc"`, `"-1/1"`. Add cases inline if real-world JSONs surface new forms. |
| Fixture JSONs drift from real Gyan ffprobe output | Verification step §8.5 catches it (real probe on Abed's box). If fixtures need adjusting, do it in the same task — not a spec change. |
| Network-only URL probes flake under CI / slow links | All unit tests mock `_run`; no real-network test in P3.1. Real-ffprobe test deferred to P3.2 (gated on `RUN_REAL_FFMPEG=1`). |
| `probe_input_video` called from an async (aiohttp) context blocks the event loop | Caller (P3.4's `_handle_cast`) will use `asyncio.to_thread(probe_input_video, url)` since `_run` is synchronous. Documented in P3.4 spec; not P3.1's concern. |
