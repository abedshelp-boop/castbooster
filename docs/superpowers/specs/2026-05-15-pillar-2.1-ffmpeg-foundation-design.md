> Sub-session 1 of Pillar 2 (transcode pipeline foundation). Parent plan:
> `~/.claude/plans/yo-we-kinda-finished-foamy-marshmallow.md`.

---

## 1. Context

Pillar 2 turns the castbooster proxy from a passthrough into a real-time video pipeline. Before any of that machinery exists, we need three primitives in place:

1. A copy of **ffmpeg** living inside the project so we can call a known version at known features.
2. A **probe module** that tells the rest of the codebase which acceleration "lane" (NVIDIA / Intel / AMD / CPU) the user's machine supports.
3. A **manual proof-of-concept** that the "take HLS apart → run a no-op filter → put HLS back together" pipeline actually plays in a media player.

P2.1 produces exactly those three primitives. No proxy changes. No transcoder module. No filter chain. Those land in P2.2 / P2.3 / P2.4.

## 2. Decisions locked in brainstorm (2026-05-15)

| # | Decision | Choice |
|---|---|---|
| B1 | **Vendor ffmpeg now** | Yes. Drop a **Gyan 8.1 full-build** Windows binary into `app/castbooster/bin/ffmpeg.exe`. Pinned, ~150 MB. Matches the version Abed already has on PATH so dev/prod behavior is identical. PATH fallback is supported via env var for advanced devs but not required. |
| B2 | **HW-accel testing strategy** | Develop on software encode (libx264) on Abed's Snapdragon machine. NVIDIA / Intel / AMD code paths get written but marked "untested-pending-hardware." Verification happens later on rented/borrowed hardware. |
| B3 | **Manual spike input** | Locally-generated HLS test pattern (10s `lavfi testsrc` at 720p30). Reproducible. No network. |
| B4 | **Manual spike success criterion** | The re-segmented output playlist plays in VLC end-to-end without error. |

## 3. Architecture

```
                       Boot
                        │
       ┌────────────────▼────────────────┐
       │       main.py startup           │
       │                                 │
       │  ffmpeg_probe.detect()          │  ← P2.1 (this spec)
       │    ↓                            │
       │  AccelProfile cached in app[]   │
       │                                 │
       └────────────────┬────────────────┘
                        │
                        ▼
                proxy / caster
                        │
                        ▼
            P2.2 transcoder spawn
            (next sub-session)
```

The probe runs **once per process** at startup. Result is cached on the aiohttp `app` object and read by the transcoder (P2.2) and any future filter modules. Re-running the probe is safe but unnecessary.

## 4. Components

### 4.1 Vendored ffmpeg binary

- **Source**: Gyan 8.1 full-build (https://www.gyan.dev/ffmpeg/builds/), specifically `ffmpeg-8.1-full_build.7z` (or `.zip` variant). Pinned by sha256 in `SOURCE.md`. Why Gyan over BtbN: matches what Abed already runs locally, single trusted maintainer with versioned URLs, full feature build includes libass + libplacebo + dav1d we want for Pillars 3/4.
- **Location**: `app/castbooster/bin/ffmpeg.exe` (plus `ffprobe.exe` for stream introspection in P2.2).
- **Size**: ~150 MB (ffmpeg) + ~150 MB (ffprobe). Acceptable per roadmap §11.6 (installer-size budget allows it).
- **Storage**: vendored in git directly for now. If repo size becomes an issue later we move to git-lfs or a `bin/.gitignore` + download-on-postinstall script. Not a P2.1 concern.
- **License compliance**: BtbN GPL build includes libx264, libx265, AOM, dav1d, etc. — all GPL-compatible. Required license notices ship with the binary as `app/castbooster/bin/LICENSE.ffmpeg.txt`. We add an entry to the future installer's About panel during Pillar 5.

### 4.2 `app/castbooster/ffmpeg_probe.py`

**Public surface:**

```python
@dataclass(frozen=True)
class AccelProfile:
    ffmpeg_path: str             # absolute path
    encoder: str                 # "h264_nvenc" | "h264_qsv" | "h264_amf" | "libx264"
    decoder: str                 # "cuda" | "qsv" | "d3d11va" | "dxva2" | "none"
    tier: str                    # "nvidia" | "intel" | "amd" | "sw"
    available_encoders: list[str]    # raw enumeration (for diagnostics)
    available_hwaccels: list[str]    # raw enumeration (for diagnostics)
    ffmpeg_version: str          # e.g. "8.1-full_build"

def detect(ffmpeg_path_override: Optional[str] = None) -> AccelProfile: ...
```

**Algorithm:**

1. **Locate ffmpeg** — in order:
   1. `ffmpeg_path_override` if passed.
   2. `CASTBOOSTER_FFMPEG` env var.
   3. `app/castbooster/bin/ffmpeg.exe` (relative to this module).
   4. `shutil.which("ffmpeg")` as final fallback.
   5. If none found → raise `FFmpegNotFoundError`.

2. **Enumerate** — `ffmpeg -hide_banner -hwaccels` and `ffmpeg -hide_banner -encoders`. Parse to lists.

3. **Encoder probe** — for each candidate in priority order `["h264_nvenc", "h264_qsv", "h264_amf", "libx264"]`, run:
   ```
   ffmpeg -hide_banner -loglevel error -f lavfi \
          -i testsrc=size=64x64:rate=1:duration=0.1 \
          -c:v <candidate> -t 0.05 -f null -
   ```
   First exit code 0 wins. Timeout 5 s per attempt. `libx264` is the always-works fallback.

4. **Decoder pick** — choose decoder that matches encoder vendor:
   - `h264_nvenc` → `cuda` if available, else `none` (SW decode is fine; encode is the bottleneck).
   - `h264_qsv` → `qsv`
   - `h264_amf` → `d3d11va`
   - `libx264` → `d3d11va` if available (free GPU decode boost on most machines including Adreno), else `dxva2`, else `none`.

   We do NOT runtime-test decoders in P2.1. ffmpeg's `-hwaccels` enumeration is trusted here. Adding runtime decoder test is a P2.2 followup if we see failures.

5. **Cache** — module-level `@lru_cache(maxsize=1)` on `detect()`. Re-call is a no-op.

**Errors:**

- `FFmpegNotFoundError` — no ffmpeg located. Fatal at app startup; `main.py` logs a friendly message and exits.
- `FFmpegProbeError` — ffmpeg located but every encoder probe failed (including libx264). Should be impossible in practice; if seen, indicates a corrupt vendor binary.

**Logging:** one info line at the end of `detect()`:
```
ffmpeg probe: path=...\ffmpeg.exe version=8.1 tier=sw encoder=libx264 decoder=d3d11va
```

### 4.3 Manual spike script

**Location**: `app/scripts/spike_p2_1.bat` (one-shot, not part of the running app).

**What it does:**

```bat
:: Generate a 10s 720p30 HLS test source WITH a 1kHz audio tone (lavfi testsrc
:: is video-only, so we mux a separate sine-wave audio input).
ffmpeg -y ^
       -f lavfi -i "testsrc=size=1280x720:rate=30:duration=10" ^
       -f lavfi -i "sine=frequency=1000:duration=10" ^
       -c:v libx264 -preset ultrafast -g 60 ^
       -c:a aac -b:a 96k ^
       -hls_time 2 -hls_list_size 0 ^
       -hls_segment_filename "%TEMP%\castbooster_spike\src\seg_%%03d.ts" ^
       -f hls "%TEMP%\castbooster_spike\src\master.m3u8"

:: Re-segment through the noop filter (mirrors what P2's transcoder will do).
:: Audio is copied (already AAC); video is re-encoded through libx264 with an
:: explicit `null` filter so we exercise the -vf code path that future filters
:: will plug into.
ffmpeg -y -i "%TEMP%\castbooster_spike\src\master.m3u8" ^
       -vf "null" ^
       -c:v libx264 -preset veryfast ^
       -c:a copy ^
       -hls_time 4 -hls_list_size 0 ^
       -hls_segment_filename "%TEMP%\castbooster_spike\out\seg_%%03d.ts" ^
       -f hls "%TEMP%\castbooster_spike\out\master.m3u8"

:: Open the output in VLC for visual confirmation
start "" "%TEMP%\castbooster_spike\out\master.m3u8"
```

**Success criterion**: VLC opens the file, plays the full 10s color-bars, no console errors. Confirms the "HLS in → noop → HLS out" pattern is sound before we wire it into the proxy in P2.4.

### 4.4 Startup wiring

`app/castbooster/main.py` gains a single line at boot:

```python
from castbooster.ffmpeg_probe import detect, FFmpegNotFoundError

try:
    accel = detect()
    log.info("ffmpeg ready: %s", accel)
except FFmpegNotFoundError as e:
    log.error("ffmpeg missing — pillar 2 features disabled (%s)", e)
    accel = None
```

`accel` is stashed on the aiohttp `app[]` object during `_on_startup` for later sub-sessions. P2.1 does not consume it beyond logging.

## 5. Testing

**Unit tests** at `app/tests/test_ffmpeg_probe.py`:

| Test | What it covers |
|---|---|
| `test_hwaccels_parser` | Parses canonical ffmpeg `-hwaccels` output into a list |
| `test_encoders_parser` | Parses ffmpeg `-encoders` output, filters to H.264 encoders |
| `test_detect_picks_libx264_on_sw_only` | Mock subprocess: nvenc/qsv/amf probes fail, libx264 succeeds → tier="sw" |
| `test_detect_picks_nvenc_when_available` | Mock subprocess: nvenc succeeds → tier="nvidia", encoder="h264_nvenc" |
| `test_detect_raises_when_no_ffmpeg` | shutil.which returns None, env var unset, bin/ empty → FFmpegNotFoundError |
| `test_detect_uses_env_override` | CASTBOOSTER_FFMPEG=/some/path → that path is used |
| `test_detect_caches_result` | Calling detect() twice runs ffmpeg subprocess only once |

**Integration test** at `app/tests/test_ffmpeg_probe_real.py` (gated on `CI=true` or `RUN_REAL_FFMPEG=1` env):

| Test | What it covers |
|---|---|
| `test_real_detect_on_this_machine` | Runs real ffmpeg, asserts result.tier in valid set, encoder is callable |

**Manual acceptance for P2.1:**

1. `cd app && .venv\Scripts\python -m pytest tests/ -v` — all green (existing 5 + new ~7).
2. `.venv\Scripts\python -c "from castbooster.ffmpeg_probe import detect; print(detect())"` — prints an `AccelProfile` whose tier matches the dev machine ("sw" on Abed's Snapdragon).
3. `app\scripts\spike_p2_1.bat` runs to completion, opens VLC, plays a 10s color-bar HLS.
4. `.venv\Scripts\python -m castbooster` boots; tray icon appears; log line `ffmpeg ready: AccelProfile(...)` visible in `%LOCALAPPDATA%\CastBooster\castbooster.log`.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Vendored ffmpeg version drifts from Gyan 8.1 on Abed's PATH | Use Gyan 8.1 or BtbN 8.1 build; document the source URL + sha256 in `app/castbooster/bin/SOURCE.md` so future replacements are traceable |
| 100 MB binary bloats git history | Tolerate for now; revisit with git-lfs if we hit problems |
| Encoder probe falsely picks a "supported" encoder that fails at full resolution | The 1-frame test isn't a stress test. Mitigation: P2.6 acceptance includes a 30-min real cast; if HW encoder degrades under load, watchdog (P5) handles fallback |
| Probe takes too long at startup (multiple ffmpeg invocations) | Each probe is <500 ms; total probe budget is ~2 s on first boot, then cached. Acceptable for a one-time startup cost |
| Future addition of AV1 / VP9 encoders changes the priority list | The candidate list is a constant in `ffmpeg_probe.py`; trivial to extend in a later pillar |
