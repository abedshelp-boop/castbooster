## 1. Context

P3.1 merged on 2026-05-19 (commit `71aff33`) — the `PipelineSpec` +
`SideTaskContext` frozen dataclasses landed plus the `pipeline_spec()`
Protocol method on `FilterStage` (returns `None` for `NoopFilter` /
`SubtitleBurnIn`, today's behavior).

P3.2 merged on 2026-05-20 (commit `bad9089`) — `RIFEFilter` + `license.py`
+ `vulkan_available()` probe + `fetch_rife.ps1` model fetcher + bundled
`rife-v4.6` model. Baseline test count after P3.2: **260 passed + 6
skipped**.

P3.3 extends `_ProcessSlot` from "1 ffmpeg subprocess" to "1 encode
ffmpeg (primary) + N side processes + 1 Python side-task Thread" so the
now-existing `RIFEFilter` can actually be spawned by the transcoder.
Tests still use a `FakeRIFEFilter` stub for state-machine control
(raise on demand / return early on demand); the real `RIFEFilter` is
exercised by the gated `RUN_REAL_FFMPEG=1` integration test. The work is process-topology +
threading + state-machine plumbing — no RIFE binary, no proxy wiring,
no UI.

**Why now:** RIFE integration (P3.2) is gated on `_ProcessSlot` knowing
how to spawn the multi-proc pipeline. Doing the slot extension as its
own sub-pillar isolates the threading work from the binary-bundling work
and keeps each PR small.

**Tier-0 guardrail applied during this brainstorm** (per the 2026-05-19
RIFE binary I/O lesson): integration assumptions about ffmpeg rawvideo
flags and Python subprocess pipe buffering were verified via context7 +
WebSearch *during* the brainstorm. See §2.3.

## 2. Locked decisions

### 2.1 From parent P3 spec (not re-litigated here)

| # | Decision | Choice |
|---|---|---|
| D1 | Integration arch | Segment-batch with continuous-I/O endpoints. Decode ffmpeg → Python side task (folder-based rife internally) → encode ffmpeg, rawvideo pipes between them. |
| D6 | Encoder retuning | `_scaled_bitrate(base, src_fps, tgt_fps) = int(base * sqrt(tgt/max(src,1.0)))` |
| §3.4 | Slot shape | `_ProcessSlot` gains `side_processes: list[Popen]`, `side_task_thread: Optional[Thread]`, `side_task_exception: Optional[BaseException]`, `side_stderr_threads: list[Thread]`. |
| §3.4 | Entry point | `slot.start(argv, pipeline_spec)` — `pipeline_spec is None` → today's single-Popen path unchanged; else `_spawn_pipeline(argv, spec)`. |
| §3.4 | WARMING criterion | encode ffmpeg has produced ≥ 2 segments **AND** all side procs alive **AND** side task hasn't raised. |
| §6 | New fatal patterns | `vulkan.*not.*found` → `vulkan_unavailable`; `failed to find.*Vulkan device` → `no_vulkan_gpu`; `model.*not.*found` → `rife_model_missing`. Case-insensitive. |
| §7 | Watchdog metrics | `Transcoder` gains `rife_fps_actual: Optional[float]`, `rife_lag_seconds: Optional[float]`, `vulkan_device_name: Optional[str]`. All initially `None`; Pillar 5 reads them. |
| §10.6 | State enumeration | Every new sub-state and transition entered in multi-proc mode MUST have at least one explicit unit test exercising entry. Acceptance criterion. |

### 2.2 New, locked this brainstorm (2026-05-20)

| # | Decision | Choice | Why |
|---|---|---|---|
| Q1 | Encode-stdin pipe buffer policy | **`bufsize=0` unbuffered** | Side task writes frame-sized chunks (~3 MB at 1080p × yuv420p × 1 frame). Python's `BufferedWriter` layer adds copies with no upside for big binary writes. Windows kernel pipe buffer (~64 KB default) is the natural backpressure point. ffmpeg-python community uses large `bufsize` for *reading*, not writing. |
| Q2 | Side-task Thread ↔ stderr-reader coord | **Reuse `_sub_state_lock` + same `_set_sub_state_locked(FAILED, …)` helper that stderr readers use.** | Pattern already proven in P2.2 (stderr-reader / watchdog-poller race). First-to-the-lock records the idle_reason; second observes FAILED / TERMINATING and short-circuits. Zero new locks. |
| Q3 | Exception propagation | **Capture into `side_task_exception`; map by type to typed `idle_reason`.** `BrokenPipeError` → `"encoder_died"` (encode-ffmpeg closed pipe first). All other exceptions → `"side_task_crashed"`. If `cancel_event` is set, exit silently — we're being torn down. | Pillar 5 watchdog consumes `idle_reason` for differentiated remediation; "encoder_died" vs "side_task_crashed" matters there. Trivial cost. |

### 2.3 Doc findings backing Q1 (context7 + WebSearch, 2026-05-20)

- ffmpeg `rawvideo` demuxer requires `framerate`, `pixel_format`,
  `video_size` explicit when reading from stdin — no header in raw
  stream. Source: ffmpeg-all docs §20.21.
- Python `subprocess.Popen(bufsize=)` semantics: `-1` → buffered with
  `io.DEFAULT_BUFFER_SIZE`; `0` → unbuffered raw I/O. Default switched
  from `0` (3.3.1) to `-1` after short-read bugs — but those bugs were
  on the *read* side. For our large-chunk *writes* to stdin, `bufsize=0`
  is the documented "pass-through" choice.
- `pipesize` parameter (Python 3.10+) is **Linux-only**; Windows ignores
  it. Windows kernel pipe buffer is ~64 KB default and cannot be
  enlarged via Popen — backpressure happens at that boundary.

## 3. Architecture

### 3.1 `_ProcessSlot` new shape

```python
class _ProcessSlot:
    # existing
    _process: Optional[subprocess.Popen]              # encode ffmpeg (primary)
    _stderr_thread: Optional[threading.Thread]
    _poller_thread: Optional[threading.Thread]
    _sub_state: _SlotState
    _sub_state_lock: threading.Lock
    _stop_requested: threading.Event
    _ready_event: threading.Event
    _idle_reason: Optional[str]
    _exit_code: Optional[int]
    _output_dir: Path
    _warming_started_monotonic: float
    _last_seg_count: int
    _last_new_seg_monotonic: float

    # NEW (P3.3)
    _side_task_thread: Optional[threading.Thread]
    _side_task_exception: Optional[BaseException]
    _side_cancel_event: threading.Event               # ctx.cancel_event for the side task
    _workdir: Optional[Path]                          # SideTaskContext.workdir; under output_dir
```

**Note on side process tracking (revised 2026-05-20).** The earlier
draft of this spec proposed `_side_processes: list[Popen]` +
`_side_stderr_threads: list[Thread]` and a `register_side_process`
callback on `SideTaskContext`. Reviewing the shipped P3.2 `RIFEFilter`,
the side task **already owns its decode subprocess internally**:
spawns it, terminates it on cancel/EOF, raises `RuntimeError` on
non-zero exit. The slot doesn't need to track decode separately —
side-process failures already route through the side task's exception
path (`RuntimeError` → wrapper catches → slot FAILED). YAGNI applies:
dropped the proc-list + stderr-threads-list fields and the
`register_side_process` callback. **`SideTaskContext` stays exactly as
P3.1 shipped it** — no contract revision in P3.3.

### 3.2 Entry point

```python
def start(self, argv: list[str],
          pipeline_spec: Optional[PipelineSpec] = None) -> None:
    """Start the slot.

    pipeline_spec is None: today's single-Popen path (no change).
    pipeline_spec is a PipelineSpec: multi-proc path.
    """
    ...
    if pipeline_spec is None:
        # existing single-Popen body
    else:
        self._spawn_pipeline(argv, pipeline_spec)
```

Backwards-compatible signature: callers that don't pass `pipeline_spec`
get today's behavior. `Transcoder` reads `chain.pipeline_spec()` from
the active `FilterChain` and forwards to `slot.start(argv, spec)`.

### 3.3 `_spawn_pipeline` flow

```
slot._spawn_pipeline(encoder_argv, spec):
  1. Create workdir under output_dir for side-task scratch
  2. Spawn encode ffmpeg with stdin=PIPE, bufsize=0, stderr=PIPE
     (argv built by _build_argv with rawvideo input — see §3.4)
  3. Attach stderr reader Thread to encode ffmpeg (same as today)
  4. Build SideTaskContext (input_url, target_fps,
     encoder_stdin=encode.stdin, workdir, cancel_event=self._side_cancel_event)
     — same SideTaskContext as P3.1 defined; no new fields.
  5. Launch side_task_thread running _side_task_wrapper(factory, ctx)
  6. Start the existing watchdog_poller Thread — extended to also
     check side_task_thread liveness + side_task_exception each tick
  7. _set_sub_state_locked(WARMING)
```

`_spawn_pipeline` does NOT spawn decode ffmpeg / rife / etc. — the
`side_task_factory` owns those subprocesses internally (P3.2's
`RIFEFilter._side_task` is the reference: spawns decode, manages
batches, terminates decode on cancel/EOF, raises `RuntimeError` on
non-zero decode/rife exit codes).

**Why no `register_side_process`:** the side task's `RuntimeError`
on inner-proc failure propagates to `_side_task_wrapper` which routes
to `side_task_crashed` (§3.5). The slot doesn't need an independent
process-list — failures already surface via the exception path.
Confirmed by reading `app/castbooster/filters/interpolation.py`
post-P3.2-merge.

### 3.4 `_build_argv` extension

When `pipeline_spec is not None`, the encoder argv changes:

```python
def _build_argv(input_url, output_dir, accel, hls_segment_seconds,
                vf_fragment="null", pipeline_spec=None, src_fps=None):
    if pipeline_spec is None:
        # existing argv path unchanged
        return [...]

    # Multi-proc: rawvideo stdin
    pix_fmt, w_h = _parse_encoder_input_format(pipeline_spec.encoder_input_format)
    argv = [
        accel.ffmpeg_path,
        "-hide_banner", "-loglevel", "info", "-nostdin",
        "-f", "rawvideo",
        "-pix_fmt", pix_fmt,
        "-s", w_h,
        "-r", str(pipeline_spec.target_fps),
        "-i", "-",
        "-vf", vf_fragment,            # typically "null" — filtering happens upstream
        "-c:v", accel.encoder,
    ]
    argv += _ENCODER_FLAGS[accel.encoder]
    argv += [
        "-r", str(pipeline_spec.target_fps),
        "-b:v", str(_scaled_bitrate(_BASE_BITRATE_BPS,
                                     src_fps or float(pipeline_spec.target_fps),
                                     pipeline_spec.target_fps)),
        "-force_key_frames", f"expr:gte(t,n_forced*{hls_segment_seconds})",
        "-c:a", "aac", "-b:a", "192k",  # P2.5 always-AAC; audio sourced separately
        "-f", "hls",
        "-hls_time", str(hls_segment_seconds),
        "-hls_playlist_type", "vod",
        "-hls_list_size", "0",
        "-hls_flags", "independent_segments",
        "-hls_segment_filename", str(output_dir / "seg_%05d.ts"),
        str(output_dir / "variant.m3u8"),
    ]
    return argv


def _parse_encoder_input_format(spec: str) -> tuple[str, str]:
    """rawvideo:yuv420p:1920x1080 → ("yuv420p", "1920x1080")."""
    parts = spec.split(":")
    if len(parts) != 3 or parts[0] != "rawvideo":
        raise ValueError(f"unsupported encoder_input_format: {spec!r}")
    return parts[1], parts[2]


def _scaled_bitrate(base_bps: int, src_fps: float, tgt_fps: int) -> int:
    import math
    return int(base_bps * math.sqrt(tgt_fps / max(src_fps, 1.0)))


_BASE_BITRATE_BPS = 3_000_000  # matches HW-encoder `-b:v 3M` in _ENCODER_FLAGS
```

**Note on audio.** Multi-proc encode ffmpeg reads rawvideo from stdin —
that's video only. Audio must come from somewhere; for P3.3 we accept
"no audio in multi-proc mode" as the stub behavior because audio
sourcing is RIFEFilter's responsibility (P3.2/P3.4 wires it through a
second input file or a separate stream — out of scope here). Tests
exercise the video-only argv shape; the `_handle_cast` integration
handles audio at the proxy level, not here.

`src_fps` is read from `probe_input_video()` (P3.1). Passed into
`_build_argv` by `Transcoder.start` / `set_filter_chain`. For unit tests,
pass it directly to `_build_argv`. If unknown (`None`), default to
`target_fps` so the sqrt ratio is 1.0 (no scaling).

### 3.5 `_side_task_wrapper`

```python
def _side_task_wrapper(self, factory, ctx):
    try:
        factory(ctx)
    except BrokenPipeError as e:
        if ctx.cancel_event.is_set():
            return  # being torn down; not a failure
        with self._sub_state_lock:
            if self._sub_state not in (_SlotState.FAILED,
                                       _SlotState.TERMINATING,
                                       _SlotState.TERMINATED):
                self._side_task_exception = e
                self._set_sub_state_locked(_SlotState.FAILED,
                                            idle_reason="encoder_died")
    except BaseException as e:
        if ctx.cancel_event.is_set():
            return
        with self._sub_state_lock:
            if self._sub_state not in (_SlotState.FAILED,
                                       _SlotState.TERMINATING,
                                       _SlotState.TERMINATED):
                self._side_task_exception = e
                self._set_sub_state_locked(_SlotState.FAILED,
                                            idle_reason="side_task_crashed")
```

### 3.6 Watchdog poller extension

The existing `_watchdog_poller_loop` runs every `_poll_interval` and
already calls `_check_process_exit_locked` for the primary process.
Extend it with a single helper called on every tick:

```python
def _check_side_task_locked(self) -> bool:
    """Returns True iff slot transitioned to FAILED. Acquires sub_state_lock briefly."""
    # side_task_thread finished (not alive) AND we're still WARMING
    # AND no exception captured AND cancel_event not set
    # → "side_task_returned_early"
    # (The wrapper handles the exception-captured case directly;
    #  this catches the unusual case where the side task returns
    #  cleanly but prematurely.)
```

New `idle_reason` tokens emitted by P3.3:
- `"encoder_died"` — wrapper, on `BrokenPipeError` (encode-ffmpeg closed pipe first)
- `"side_task_crashed"` — wrapper, on any other exception out of the side task
- `"side_task_returned_early"` — poller, side task returned without exception
  while still in WARMING

Plus 3 fatal-pattern reasons from §2.1:
- `"vulkan_unavailable"` — encoder stderr matched
- `"no_vulkan_gpu"` — encoder stderr matched
- `"rife_model_missing"` — encoder stderr matched (would only fire if rife
  output a stderr line through the encoder — unlikely in practice; rife is
  a side subprocess. Kept for symmetry per parent P3 spec §6.)

Total new idle_reasons: **6**.

### 3.7 stop() / cancel propagation

Existing `stop()` is extended to:
1. Set `_side_cancel_event` **before** writing `q\n` to encoder stdin
   — so the side task starts winding down before the encoder closes
   its stdin from the other side. The side task's loop checks
   `cancel_event` at the top of each batch; the inner `decode.terminate()`
   in the side task's `finally` block kills the decode subprocess.
2. Drain encoder via `q\n` (existing).
3. Join `side_task_thread` with a bounded budget (default
   `drain_seconds + 2.0s` extra for the side task's cleanup).
4. If `side_task_thread` doesn't join in budget: log the leak, continue.
   (Daemon thread; process exit will reap it. We don't have a clean way
   to force-kill the underlying decode subprocess from outside the
   side task — P3.2's `RIFEFilter` is responsible for its own decode
   teardown.)
5. Join encoder stderr reader (existing pattern).
6. `_cleanup_output_dir` (existing).

`workdir` lives under `output_dir`; `rmtree` of `output_dir` cleans it.

### 3.8 `FilterChain` plumbing

`Transcoder.start` and `Transcoder.set_filter_chain` must extract the
`pipeline_spec` from the active chain and pass it to `slot.start`:

```python
def _spec_from_chain(chain: FilterChain) -> Optional[PipelineSpec]:
    """Return the first non-None pipeline_spec() in the chain, or None.

    Raises ValueError if more than one stage returns a non-None spec
    — P3.3 is YAGNI on multi-PipelineSpec chains; no real filter
    needs that yet.
    """
    spec: Optional[PipelineSpec] = None
    for stage in chain.stages:
        s = stage.pipeline_spec()
        if s is None:
            continue
        if spec is not None:
            raise ValueError(
                "FilterChain has more than one stage returning a "
                "PipelineSpec — not supported in P3.3"
            )
        spec = s
    return spec
```

`FilterChain` currently keeps `self._stages` private — add a public
`stages: tuple[FilterStage, ...]` read-only property for this use.

## 12. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Side-task Thread leaks on stop() | `stop()` always sets `_side_cancel_event` first; wrapper exits silently when cancel_event is set; bounded `Thread.join`. Daemon-thread fallback if join times out. P3.2's `RIFEFilter._side_task` already terminates its inner decode in a `finally`. Tested by M-STOP-*. |
| `bufsize=0` regresses single-Popen path | Single-Popen path is unchanged — only the multi-proc encoder's Popen uses `bufsize=0`. Existing 260 tests prove the single-Popen path stays green. |
| Race: side_task crashes AND encoder stderr matches a fatal pattern simultaneously | Both call `_set_sub_state_locked(FAILED, …)` under the same lock. First-to-lock wins; second observes FAILED and short-circuits. Idle_reason is the first-to-land — non-deterministic between them, but both reasons map to "this slot is dead" so the choice doesn't matter for behavior. Tested by M-FAIL-3 (BrokenPipe vs encoder die race). |
| `FilterChain.stages` becoming public breaks encapsulation | Make it a tuple property (read-only); callers can't mutate. |
| Implementer discovers an unenumerated transition mid-task | §7 explicit instruction: STOP, update §4, add test, continue. Do NOT silently land. |
| 18 new tests on top of 260 → CI time | Each test is ~50ms with `_poll_interval=0.05`. Adds ~1s wall time. Acceptable. |
| Spec changed mid-execution from what was approved at brainstorm | Recorded inline in §3.1 + §3.3 — `register_side_process` and `side_processes` list were dropped after reading P3.2's shipped RIFEFilter. Brainstorm's 3 locked decisions (Q1 bufsize=0, Q2 lock reuse, Q3 typed idle_reason) are unchanged. |
