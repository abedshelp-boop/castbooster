## 1. Context

P2.1–P2.3 shipped the transcode pipeline as a leaf module. `Transcoder`
produces local HLS at `<base>/v1/`, exposes a 10-state machine
(`IDLE → SPAWNING → WARMING → READY → STREAMING ↔ STALLED`, plus
`RELOADING / FAILED / TERMINATING / TERMINATED`), and supports hot
filter-chain swap via `set_filter_chain()`. **Nothing in `proxy.py`
consumes it yet.** Every real cast still goes the Phase 1 passthrough
path: `/s/<token>/master.m3u8` → `_handle_entry` → `_proxy_fetch`.

P2.4 wires the transcoder into the cast path. After this session, every
cast goes:

```
Chromecast → /s/<token>/output/master.m3u8 (transcoder's local HLS on disk)
                ↑
          ffmpeg subprocess (one per cast session)
                ↑
   ffmpeg INPUT = http://127.0.0.1:38123/s/<token>/upstream/master.m3u8
                ↑
          existing _proxy_fetch (cookies / Referer / UA reuse, unchanged)
                ↑
          upstream streaming site
```

This is the highest-risk single piece in Pillar 2 — it touches every
cast. Mitigations: env-flag escape hatch (`CASTBOOSTER_PASSTHROUGH=1`),
gated real-ffmpeg integration test before merge, mandatory
real-Chromecast acceptance test before merge, and a production-code
escalation rule on every test-only subagent prompt (per the 2026-05-15
Round 9 lesson).

## 2. Decisions locked in brainstorm (2026-05-15)

| # | Decision | Choice | Rationale |
|---|---|---|---|
| D1 | FAILED-state fallback | **(c) Hybrid** — set `session.passthrough_only=True`, retry via `/upstream/*`, log a WARN `[cast]` line with `idle_reason`, increment an in-memory `failure_counter`. | User always sees their video, AND we get a paper trail to find bugs. Counter being non-zero in the wild is a paging signal. |
| D2 | READY budget | **Per-tier** (using `AccelProfile.tier`): 6 s for `nvidia` / `intel` / `amd` (hardware-encoder tiers), 12 s for `sw` (libx264). Passed as `Transcoder(..., warming_timeout=budget)`. Same value also gates `_handle_cast`'s `wait_until_ready`. | 2 s segment_duration + ~1 s ffmpeg cold start + ~2 s first-segment-write + slack. Hardware encoders write first segment ≤ 4 s typically; sw can take 6–8 s on cold cache. Per-tier surfaces NVENC failures in half the time without giving sw false-positive timeouts. |
| D3 | `/upstream/*` visibility | ~~**127.0.0.1 only.** Reject non-loopback `request.remote` with `403`.~~ **AMENDED 2026-05-16: LAN-accessible, no gate.** Discovered during Task 8 (gated real-ffmpeg integration) that the loopback gate is incompatible with the FAILED-fallback path: when a transcoder fails and the cast falls back to passthrough, the Chromecast (a LAN device) needs to fetch `/upstream/master.m3u8` directly — the gate would 403 it and break the "(c) hybrid" promise from D1. The 128-bit uuid4 token is the security boundary; gate dropped. | Original D3 rationale was defense-in-depth against a token leak via logs. The token IS still 128-bit unguessable; an attacker reading our logs is already past our security perimeter. The cost (breaking FAILED-fallback on LAN) was greater than the benefit. |
| D4 | `[cast]` log level | **INFO**. | Matches `[proxy fetch …]`, `[media status …]`, `[keepalive …]` precedent. Real-world bug reports need the timing trail. |
| D5 | Transcoder-stop wiring | `cm.play(uuid, url, ct, on_session_end=cb)` — CastManager fires `cb` from `_release_wakelock_for(uuid)`. | One wire-up covers user-stop / TV-finishes / device-removed. CastManager stays transcoder-ignorant. |
| D6 | Transcoder spawn timing | **Lazy** — spawn at `_handle_cast`, not at `register_stream`. | Eager-warm-on-register is a P5 optimization. No wasted ffmpeg if user closes the popup without casting. |

**D1 failure counter shape:** module-level dict
`{"total": int, "by_reason": {reason: int}}` on `CastManager`, mutated
under `self._lock` (already exists). Exposed via a new
`cm.transcoder_failure_stats()` method that P2.7 / tray menu can read
later. No persistence — resets on app restart.

**D2 per-tier table:**

| AccelProfile.tier | warming_timeout |
|---|---|
| `nvidia` / `intel` / `amd` (hardware) | 6.0 s |
| `sw` (libx264 software) | 12.0 s |

## 3. Architecture

### 3.1 Route map

aiohttp matches literal segments before falling back to dynamic, so
registration order is irrelevant. Verified via context7 against
`/aio-libs/aiohttp` 2026-05-15: *"Fixed paths are prioritized over
dynamic paths. For dynamic paths with the same prefix, the order of
registration determines precedence."* — our `/upstream/...` and
`/output/...` differ in their first literal segment after the dynamic
token, so they're unambiguous.

**Renamed (no handler change, no behavior change):**

| Old route | New route | Handler |
|---|---|---|
| `GET /s/{token}/master.m3u8` | `GET /s/{token}/upstream/master.m3u8` | `_handle_entry` (unchanged internally; wrapped by `_require_loopback`) |
| `GET /s/{token}/manifest.mpd` | `GET /s/{token}/upstream/manifest.mpd` | same |
| `GET /s/{token}/video.mp4` | `GET /s/{token}/upstream/video.mp4` | same |
| `GET /s/{token}/video.webm` | `GET /s/{token}/upstream/video.webm` | same |
| `GET /s/{token}/video` | `GET /s/{token}/upstream/video` | same |
| `GET /s/{token}/fetch` | `GET /s/{token}/upstream/fetch` | `_handle_fetch` (unchanged internally; wrapped by `_require_loopback`) |
| `OPTIONS /s/{token}/...` (each) | `OPTIONS /s/{token}/upstream/...` (each) | `_handle_options` |

Cookie/Referer/UA reuse is keyed by the session token in the URL path,
which survives the rename verbatim. `_proxy_fetch`, `_cookies_for_host`,
`_build_upstream_headers`, `_looks_like_playlist`, `_is_playlist_body`,
`_infer_segment_content_type`, `_CORS_HEADERS` — none touched.

**New (transcoder output):**

| Route | Handler | Behavior |
|---|---|---|
| `GET /s/{token}/output/master.m3u8` | `_handle_output_manifest` | Resolve session → check `transcoder.state` → if alive (READY / STREAMING / STALLED / RELOADING) stream `transcoder.output_dir / "master.m3u8"` from disk with CORS + `application/vnd.apple.mpegurl`. Otherwise `503` with JSON body `{"state": ..., "idle_reason": ...}`. |
| `GET /s/{token}/output/variant.m3u8` | `_handle_output_manifest` (same) | Chromecast may fetch the variant playlist separately depending on how it parses the master. |
| `GET /s/{token}/output/seg_{n:\d{5}}.ts` | `_handle_output_segment` | Resolve session → 503 if not alive → stream `transcoder.output_dir / f"seg_{n}.ts"` from disk. The 5-digit regex constraint keeps matching tight. |
| `OPTIONS /s/{token}/output/...` (each) | `_handle_options` | CORS preflight. |

**`/upstream/*` loopback gate:** new helper `_require_loopback(request)`
returns `web.Response(status=403, text="loopback only")` if
`request.remote not in {"127.0.0.1", "::1"}`. Applied at the route
handler level (not as middleware) so `/health`, `/nm`, and `/output/*`
stay LAN-accessible.

### 3.2 `_handle_cast` rewrite

The full happy-path is 6 steps. Each step emits an `[cast]` INFO log
line (see §3.5).

```
1. Resolve session by token.                                        # 404 if unknown
2. Read env CASTBOOSTER_PASSTHROUGH.
   If truthy → set session.passthrough_only=True, log [cast] env override.
3. If session.passthrough_only:
       playback_url = http://{lan_ip}:38123/s/{token}/upstream/{cosmetic-suffix}
       skip transcoder; go to step 5.
4. Else:
       a. Build base_output_dir = Path(tempfile.gettempdir()) / "castbooster" / token
       b. Read cached AccelProfile from app["accel_profile"] (detected at startup).
       c. Choose warming_timeout from per-tier table (D2).
       d. Construct Transcoder(
              input_url=http://127.0.0.1:38123/s/{token}/upstream/master.m3u8,
              base_output_dir=base, accel=accel,
              filter_chain=FilterChain([NoopFilter()]),
              warming_timeout=warming_timeout)
       e. Store transcoder + output_dir on session (additive fields).
       f. transcoder.start()  # non-blocking; subprocess + threads spin up
       g. Log [cast] warming start.
       h. result = transcoder.wait_until_ready(timeout=warming_timeout)   # blocks
       i. If result is True (state ∈ {READY, STREAMING, STALLED}):
              Log [cast] READY in <elapsed>s.
              playback_url = http://{lan_ip}:38123/s/{token}/output/master.m3u8
              go to step 5.
          Else (state == FAILED OR timeout):
              reason = transcoder.idle_reason or "warming_timed_out"
              Log [cast] FAILED reason=<reason> elapsed=<elapsed>s.
              Increment cm.transcoder_failure_stats counter.
              transcoder.stop()  # best-effort; rmtree the partial output_dir
              session.transcoder = None
              session.output_dir = None
              session.passthrough_only = True
              playback_url = http://{lan_ip}:38123/s/{token}/upstream/{cosmetic-suffix}
              Log [cast] falling back to passthrough.
              go to step 5.

5. Build on_session_end callback:
       def _on_end():
           t = session.transcoder
           if t is not None and t.state not in (TERMINATING, TERMINATED):
               t.stop()
           session.transcoder = None
6. cm.play(uuid, playback_url, content_type, on_session_end=_on_end) via executor.
   Log [cast] play_media → <playback_url>.
   Return {"status": "ok", "playbackUrl": playback_url, ...}.
```

`content_type` is `application/vnd.apple.mpegurl` for transcoded output
(the transcoder always emits HLS). Passthrough output falls back to
`_guess_manifest_path` for non-HLS inputs (manifest.mpd / video.mp4 /
video.webm).

### 3.3 `StreamSession` extension (3 additive fields)

`app/castbooster/session_store.py` — add three fields, no
restructuring:

```python
@dataclass
class StreamSession:
    token: str
    upstream_url: str
    cookies: List[Dict[str, Any]] = field(default_factory=list)
    headers: Dict[str, str] = field(default_factory=dict)
    user_agent: str = ""
    created_at: float = field(default_factory=time.time)
    # NEW in P2.4 — all default None / False so existing tests don't need updates.
    transcoder: Optional["Transcoder"] = None   # forward-ref string to avoid import cycle
    output_dir: Optional[Path] = None           # the base, before /v1/
    passthrough_only: bool = False
```

Forward-reference string for `Transcoder` keeps `session_store`
independent of `transcoder` (no module import cycle). Reachable via
`TYPE_CHECKING` import for type hints.

`SessionStore` gains no new methods. No `remove()`. Existing
`prune_older_than` is left as-is; transcoders are stopped via the
on_session_end callback path, not via session pruning. (Stopping a
transcoder during pruning is a P2.6 task — out of scope here.)

### 3.4 CastManager `on_session_end` callback

`app/castbooster/caster.py` — `play()` grows one kwarg, dispatch grows
one line.

```python
def play(
    self,
    uuid_str: str,
    url: str,
    content_type: str,
    *,
    on_session_end: Optional[Callable[[], None]] = None,
    log_token: Optional[str] = None,
) -> str:
    ...
    # Stash the callback per-uuid (under self._lock) BEFORE play_media,
    # so a fast-failing cast still fires the callback during _release_wakelock_for.
    with self._lock:
        if on_session_end is not None:
            self._session_end_callbacks[uuid] = on_session_end
    # log_token is threaded into _MediaStatusLogger so its first-PLAYING
    # log line carries the [cast token=...] tag.
    ...  # existing: register status listener, play_media, block_until_active, wakelock, keepalive
```

`_release_wakelock_for(uuid)` (caster.py:300) fans out the callback at
the very end, after wakelock release + keepalive stop:

```python
def _release_wakelock_for(self, uuid: UUID) -> None:
    ...  # existing wakelock + keepalive cleanup unchanged
    with self._lock:
        cb = self._session_end_callbacks.pop(uuid, None)
    if cb is not None:
        try:
            cb()
        except Exception:
            log.exception("on_session_end callback failed")
```

This covers ALL THREE end paths because they ALL funnel through
`_release_wakelock_for`:

- user-stop: `cm.control(action='stop')` → `_release_wakelock_for`
- TV-finishes: `_MediaStatusLogger.on_idle` → `_release_wakelock_for`
- device-removed: `_on_remove` → `_release_wakelock_for`

`_session_end_callbacks: Dict[UUID, Callable[[], None]]` is a new
instance attribute on `CastManager`, initialized in `__init__` next to
`_wakelock_held`.

**Play-during-play race (bake this into Task 4).** If `play()` is
called twice on the same uuid without an intervening
`_release_wakelock_for(uuid)` (rare — user clicks Cast on a second
source before stopping the first), the second call would overwrite the
first callback and the first transcoder would leak. The `play()`
implementation MUST detect overwrite and fire the previous callback:

```python
def play(self, uuid_str, url, content_type, *, on_session_end=None, log_token=None) -> str:
    ...
    prev_cb: Optional[Callable[[], None]] = None
    with self._lock:
        if on_session_end is not None:
            prev_cb = self._session_end_callbacks.get(uuid)
            self._session_end_callbacks[uuid] = on_session_end
    # Fire previous outside the lock — it may call transcoder.stop()
    # which is slow on Windows (rmtree). on_session_end is required to be
    # idempotent (Transcoder.stop is, by design from P2.2).
    if prev_cb is not None and prev_cb is not on_session_end:
        try:
            prev_cb()
        except Exception:
            log.exception("previous on_session_end callback failed during play() overwrite")
    ...
```

Tested by adding `test_play_twice_on_same_uuid_fires_previous_callback`
to `test_on_session_end.py` (bumps that file to 4 tests).

### 3.5 Logging discipline

Every cast produces a continuous `[cast]` INFO trail. Token is truncated
to 8 hex chars for readability:

```
[cast token=abc12345] start uuid=550e8400-... upstream_host=masukestin.com
[cast token=abc12345] env CASTBOOSTER_PASSTHROUGH=0; spawning transcoder accel=h264_nvenc/cuda/nvidia budget=6.0s
[cast token=abc12345] transcoder WARMING base=C:\Users\Abeds\AppData\Local\Temp\castbooster\abc12345\

[cast token=abc12345] play_media → http://192.168.1.x:38123/s/abc12345/output/master.m3u8
[cast token=abc12345] media_status first PLAYING after 1.18s
```

The last line is emitted by `_MediaStatusLogger` on its
`self._seen_active` transition (the `log_token` kwarg of `cm.play()`

Failure trail:

```
[cast token=abc12345] start uuid=... upstream_host=masukestin.com

[cast token=abc12345] falling back to passthrough; session.passthrough_only=True
[cast token=abc12345] play_media → http://192.168.1.x:38123/s/abc12345/upstream/master.m3u8
```

INFO level. `log = logging.getLogger(__name__)` already present at the
top of `proxy.py`.

### 3.6 Escape hatch (`CASTBOOSTER_PASSTHROUGH=1`)

Read once per `_handle_cast` invocation via
`os.environ.get("CASTBOOSTER_PASSTHROUGH", "")`. Truthy strings: `"1"`,
`"true"`, `"yes"` (case-insensitive). Anything else → transcoder path.

Undocumented for end users. Mentioned in `SESSION_HANDOFF.md` after
P2.4 ships as a dev-only lifesaver. Logged at startup if set:
`log.warning("CASTBOOSTER_PASSTHROUGH=1 — transcoder bypassed; every cast is passthrough")`.
The startup warning goes in `__main__.py` (or `main.py`, wherever the
log import is first established).

### 3.7 AccelProfile caching

`ffmpeg_probe.detect()` is called once at proxy startup
(`_on_startup`), cached on the app dict as
`app["accel_profile"] = AccelProfile(...)`. `_handle_cast` reads from
the dict (no per-cast probe — probing forks ffmpeg, which is slow).

`detect()` raises `FFmpegNotFoundError` if no ffmpeg binary is located
and `FFmpegProbeError` if every encoder candidate fails the runtime
probe. Both are non-recoverable for the transcoder path but should NOT
crash the proxy startup — the passthrough path is still viable.
`_on_startup` MUST wrap the call:

```python
try:
    app["accel_profile"] = ffmpeg_probe.detect()
except (FFmpegNotFoundError, FFmpegProbeError) as e:
    log.warning("ffmpeg probe failed (%s); every cast will use passthrough", e)
    app["accel_profile"] = None
```

When `app["accel_profile"]` is `None`, `_handle_cast` forces passthrough
for that cast and logs `[cast token=...] no AccelProfile available;
forcing passthrough` at WARN level. The session is marked
`passthrough_only=True` so re-casts on the same session skip the
re-probe entirely.

### 3.8 Playlist URL rewriting + fetch route extension (AMENDED 2026-05-16)

Two related fixes surfaced during Task 8's gated real-ffmpeg integration test.

**Bug 1 — hardcoded port in playlist rewrite.** `_proxy_fetch`'s
playlist rewrite formerly used
`f"http://{request.app['lan_ip']}:{PROXY_PORT}"` as the proxy_base for
segment-URL rewriting. The hardcoded port breaks when the proxy listens
on any port other than 38123 — segment URLs in the rewritten playlist
point at nothing.

**Fix 1:** rewrite using `request.host` (which carries both host AND
port of the actual incoming request):

```python
proxy_base = f"http://{request.host}"  # e.g. "192.168.1.10:38123" or "127.0.0.1:61806"
```

In production this is identical behavior — `request.host` is
`"<lan_ip>:38123"` because clients reach the proxy via that bound port.
In tests `request.host` reflects the TestServer's random port. No
regression; cleaner correctness.

**Bug 2 — ffmpeg HLS demuxer rejects extension-less segment URLs.**
Modern ffmpeg (verified against the N-124462 vendored build) refuses
to fetch HLS segments unless the URL path ends in a recognized
extension. Our rewritten URLs used `/s/{token}/upstream/fetch?u=<b64>`
(no path extension), producing:

```
URL .../upstream/fetch?u=... is not in allowed_segment_extensions,
consider updating hls.c and submitting a patch to ffmpeg-devel
```

→ ffmpeg returns "Invalid data found when processing input" → our
fatal-pattern classifier sees that → transcoder transitions to FAILED
with `idle_reason=input_unreachable`.

**Fix 2:** rename the fetch route from `/upstream/fetch` to
`/upstream/fetch.ts`. The literal `.ts` satisfies ffmpeg's extension
check. The handler ignores the suffix (still reads the encoded URL
from the `u` query param). Mirror the rename in `hls_rewriter._wrap`.

```python
# hls_rewriter.py
return f"{proxy_base}/s/{token}/upstream/fetch.ts?u={encode_url(absolute)}"

# proxy.py route registration
app.router.add_get("/s/{token}/upstream/fetch.ts", _handle_fetch)
app.router.add_route("OPTIONS", "/s/{token}/upstream/fetch.ts", _handle_options)
```

The 5 hls_rewriter unit tests were updated to expect the new path.

### 3.9 Async-loop discipline (AMENDED 2026-05-16)

All blocking `Transcoder` methods (`start()`, `wait_until_ready(timeout)`,
`stop(drain_seconds)`) MUST be offloaded to the event-loop default
executor via `await loop.run_in_executor(None, ...)` when invoked from
an `async def` aiohttp handler.

**Why:** ffmpeg fetches from the proxy's `/upstream/*` routes over a
loopback HTTP socket. If the asyncio event loop is blocked (e.g. by a
synchronous `transcoder.wait_until_ready` call inside `_handle_cast`),
incoming TCP connections from ffmpeg sit in the OS accept backlog and
never reach an aiohttp handler. ffmpeg blocks in pre-connect, produces
no stderr, and the warming budget elapses with no actual HTTP traffic —
exactly the `warming_timed_out` failure mode observed in the 2026-05-16
real-Chromecast acceptance pass (Task 9). Every cast fell through to the
passthrough fallback; the transcoder pipeline was never exercised
end-to-end despite "video plays".

The smoking gun in the 2026-05-16 repro: a 14-second gap in
`aiohttp.access` log entries for `/health` (Chrome extension polls every
1–2 s) coinciding exactly with the WARMING → FAILED window. The proxy
process was alive but its event loop was frozen — not a network bug, not
an ffmpeg bug, a synchronous-wait-in-async-handler bug.

The gated real-ffmpeg test (§4.7) already encodes the correct pattern:

```python
loop = asyncio.get_running_loop()
ready = await loop.run_in_executor(
    None, transcoder.wait_until_ready, warming_timeout
)
```

This amendment promotes that implicit test convention to an explicit
spec requirement. `_handle_cast` defines `loop` once at the top of the
handler and uses it for all four offloaded calls (`start`, `wait_until_ready`,
both `stop` paths). A mocked unit-test regression (§4.5) was added to
catch any future re-introduction by asserting event-loop responsiveness
during the warming wait.

The `Transcoder` API itself is unchanged — `start/wait_until_ready/stop`
remain blocking by design (they own threads + subprocess). The
discipline lives entirely on the caller side.

## 7. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Path-prefix collision between `/upstream/*` and `/output/*` | aiohttp's literal-segment-first matching disambiguates (context7 verified). `test_upstream_and_output_under_same_token_no_collision` exercises both routes concurrently. |
| ffmpeg's HTTP fetch pattern doesn't work cleanly through `_proxy_fetch` | Gated real-ffmpeg integration test (§4.7) flushes this out BEFORE merge. Implementer-prompt escalation clause forces any `_proxy_fetch` fix to land in a separate task. |
| RELOADING handled as "ended" by `/output/*` handler | Tested by `test_output_master_200_when_reloading`. State predicate is `{READY, STREAMING, STALLED, RELOADING}` not just `READY`. IDLE-race lesson applied to the new state. |
| FAILED fallback masks regressions | (D1's tradeoff.) Mitigated by INFO `[cast]` failure log + failure counter exposed via `cm.transcoder_failure_stats()`. The counter being non-zero in the wild is a paging signal. |
| READY budget too short on cold machine | Per-tier budget (D2). SW gets 12 s. If a real user reports timeouts, bump the table — single source of truth. |
| Transcoder leaked on app crash | Out of scope for P2.4 (P2.6 30-min soak covers it). For P2.4 the on_session_end wiring covers normal-path cleanup. |
| Existing 108-test suite regresses | All API additions are additive (new kwargs default None, new fields default None/False, new helpers don't replace existing ones). Run full suite green at each task boundary. |
| Round 9-style scope drift recurring | Test happy-path walkthrough (§4) pre-identifies the two production-code edits required (`_require_loopback` helper + state-predicate-with-RELOADING). Both land in explicit tasks, NOT discovered during integration tests. Every test-only subagent prompt includes the escalation clause verbatim. |
| Counter race between concurrent casts | Mutation under `cm._lock` (existing). `transcoder_failure_stats()` returns a deep-copy snapshot under the same lock. |
