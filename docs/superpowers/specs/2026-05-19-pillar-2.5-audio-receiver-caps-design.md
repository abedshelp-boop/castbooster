## 1. Decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| A1 | Audio strategy | Always re-encode to AAC 192k | Fixes AC3/EAC3 silent-playback bug on Chromecast 3rd gen. Simpler than ffprobe-then-branch (no spawn delay, no fallback path). Generation-loss imperceptible at 192k. ~1-2% CPU cost is acceptable. |
| A2 | Bitrate | 192k | Standard high-quality AAC for stereo TV playback. 128k considered; 192k chosen for headroom on action/music-heavy anime. |
| C1 | Where caps live | New module `receiver_caps.py` | Pure data + lookup. No I/O. Easy to test in isolation. |
| C2 | API shape | `CastManager.capabilities(uuid_str) -> ReceiverCaps` | One call from `proxy.py` per cast. Returns frozen dataclass. |
| C3 | Wiring into transcoder | **Deferred to P3** | Today the transcoder outputs 1080p30 H.264 — every Chromecast handles it. Caps info has no effect on argv today. P3 (RIFE@60fps) is the first real consumer. |
| C4 | Unknown / ambiguous models | Conservative fallback (1080p30 H.264 AAC, no HEVC/AV1/AC3) | pychromecast reports `"Chromecast"` for 1st/2nd/3rd gen indistinguishably — can't safely promote 3rd gen to 1080p60 without manual override. Safe default never breaks. |

## 2. Interfaces

### `receiver_caps.py`

```python
@dataclass(frozen=True)
class ReceiverCaps:
    tier: str            # "ultra" | "gtv" | "3rd_gen_or_older" | "audio_only" | "unknown"
    max_width: int       # 1920 | 3840
    max_height: int      # 1080 | 2160
    max_fps: int         # 30 | 60
    supports_h265: bool
    supports_av1: bool
    supports_ac3: bool
    supports_eac3: bool
    audio_only: bool     # Nest Hub / Nest Audio / etc.

def capabilities_for_model(model_name: str) -> ReceiverCaps: ...
```

**Table (by model_name string from pychromecast):**

| `model_name` | tier | res | fps | h265 | av1 | ac3 | eac3 | audio_only |
|---|---|---|---|---|---|---|---|---|
| `"Chromecast Ultra"` | ultra | 3840×2160 | 60 | ✅ | ❌ | ✅ | ✅ | ❌ |
| `"Chromecast"` (gen ambiguous) | 3rd_gen_or_older | 1920×1080 | 30 | ❌ | ❌ | ❌ | ❌ | ❌ |
| `"Chromecast HD"` (Google TV HD) | gtv | 1920×1080 | 60 | ✅ | ✅ | ✅ | ✅ | ❌ |
| `"Chromecast 4K"` / `"Google TV"` | gtv | 3840×2160 | 60 | ✅ | ✅ | ✅ | ✅ | ❌ |
| `"Google Nest Hub"`, `"Google Home Hub"` | audio_only | 0 | 0 | ❌ | ❌ | ❌ | ❌ | ✅ |

### `caster.py` addition

```python
class CastManager:
    def capabilities(self, uuid_str: str) -> ReceiverCaps:
        """Look up the receiver's capabilities by uuid.
        Returns conservative defaults (tier='unknown') if uuid not discovered."""
```

### `transcoder.py` audio argv change

## 3. State machine impact

None. The audio change is in the static argv list and runs through the same ffmpeg invocation. No new states, no new transitions. Per the 2026-04-22 lesson: enumerated and verified — SPAWNING, WARMING, READY, STREAMING, STALLED, RELOADING, FAILED, TERMINATING, TERMINATED all unaffected. The `_ProcessSlot` lifecycle is identical.

## 4. Tests

- **`tests/test_receiver_caps.py`** (NEW) — every table row asserted, unknown-model fallback, empty string fallback.
- **`tests/test_caster_capabilities.py`** (NEW) — `CastManager.capabilities()` for: known uuid → matching caps; unknown uuid → unknown fallback. Uses the existing `_make_manager_with_fake_connection` helper pattern from `test_on_session_end.py`.

## 5. Risk + rollback

**Risk: low.**
- Audio re-encode adds CPU load. SW transcoding on Abed's machine currently runs at ~22× realtime; AAC encode is well under 1% of that budget.
- Capability table is pure data. Wrong row only matters when P3 starts gating on caps — caught then, fixed there.
- Three failure modes: (a) audio re-encode breaks ffmpeg argv → caught by argv assertion; (b) capabilities() throws on unknown uuid → covered by unknown-uuid test; (c) model_name string drift on new Chromecast hardware → fallback to conservative defaults, never breaks playback.

**Rollback**: per-commit revert. No data migration, no schema change.

---

## 6. Out of scope (explicit)

- ffprobe-based audio branch — replaced by always-re-encode (A1).
- Wiring `ReceiverCaps` into the transcoder argv — P3.
- HEVC / AV1 encode paths — table notes them; we don't emit them yet.
- Audio-only device refusal logic — table notes it; refusal/UI is P3+.
- Receiver-side error recovery — Pillar 5.
- Audio bitrate adaptation (192k is fixed for all) — revisit if anyone complains.

---

## 7. Acceptance

Spec is "done" for shipping when:
1. `receiver_caps.py` exists, table populated, `capabilities_for_model()` covers every documented model_name + fallback.
2. `CastManager.capabilities()` returns correct caps for discovered uuid + conservative defaults for unknown.
3. `_build_argv` produces argv containing `-c:a aac` + `-b:a 192k` adjacent flag pairs.
4. Full suite green: 169 + ~8 new = ~177 passed + 5 skipped.
5. Manual: cast a non-AAC source (any anime with AC3 audio — Abed picks one) on a real Chromecast and confirm audio plays. Optional — happy path is the bug we're fixing.
6. Commits merged to master.
