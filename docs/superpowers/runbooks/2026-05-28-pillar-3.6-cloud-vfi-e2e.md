# Pillar 3.6 — Cloud VFI E2E Runbook

## Goal of one E2E run

Get smooth (RIFE 2x) anime visible on Abed's TV via Chromecast, with the
cloud orchestrator on the laptop spinning up a RunPod RTX 4090/6000 Ada
pod on demand, running RIFE TRT FP16 → NVENC h264 → HLS, terminating
the pod after the cast ends, and showing the warmup card on the popup.

This runbook is the human-driven counterpart to the unit + integration
test suite. The suite (`pytest -v`) verifies the orchestrator wiring
locally; this runbook verifies the wiring SURVIVES contact with real
RunPod, real Chromecast, and a real anime source URL.

## Required state before starting

### Both repos pushed to GitHub

- [ ] `Chrome-cast-extension`: `master` branch (HEAD ≥ 84b0537) pushed to `origin`.
- [ ] `castbooster-cloud-worker`: `pillar-3.6-source-proxy` branch pushed to `origin` AND tagged as `v0.3.1`. GHA build for the tag must complete (~21min on cold cache); image must be pullable as `ghcr.io/abedshelp-boop/castbooster-cloud-worker:v0.3.1`.

Verify: `docker pull ghcr.io/abedshelp-boop/castbooster-cloud-worker:v0.3.1` works (after `docker login ghcr.io` if needed). Image size ~5-8GB so it's a 5-10min download.

### Laptop env configured

`.env` at the Chrome-cast-extension repo root (gitignored). Required vars:

```bash

# From https://runpod.io/console/user/settings → API Keys

CLOUD_GPU_TYPES=NVIDIA GeForce RTX 4090,NVIDIA RTX 6000 Ada Generation,NVIDIA RTX A6000
```

### Hardware on

- [ ] Chromecast powered on, same Wi-Fi as laptop.
- [ ] TV input switched to the Chromecast.
- [ ] Laptop on charger (cast is 10-30min; don't run on battery).

### RunPod budget acknowledged

- One cast = ~10min wall time at ~$0.70-1.20/hr depending on which GPU got allocated → ~$0.12-0.20 per cast.
- First-time image pull adds 3-6min of pod-idle time → ~$0.05 extra.
- Worst-case budget for the first E2E session: $1.00 (allows 4-5 attempts if any fails).

## Step-by-step

### Stage 1 — Sanity smoke (no cookies)

Use the mux test stream first. Confirms the cloud orchestrator + RunPod + v0.3.0/v0.3.1 base path work without the egydead cookie/header complexity.

Source URL: `https://test-streams.mux.dev/x36xhzz/x36xhzz.m3u8` (public HLS, no auth, free CDN).

1. [ ] Start the laptop app: `cd "C:/Users/Abeds/Cursor projects/Chrome-cast-extension/app" && .venv/Scripts/python.exe -m castbooster`
2. [ ] Open Chrome with the castbooster extension loaded (Manage Extensions → Developer Mode → Load Unpacked → point at `Chrome-cast-extension/extension/`).
3. [ ] Click the castbooster icon. Smooth-motion toggle should be ON (or flip it on; requires Pro license — temporarily set in env or stub).
4. [ ] Open the test stream URL above in a Chrome tab.
5. [ ] Click "Cast" in the castbooster popup. Pick the Chromecast device.
6. [ ] Watch the popup:
   - [ ] The warmup card appears with "Reserving GPU…".
   - [ ] Within 20-60s, transitions through "Booting cloud worker…" → "Compiling engine + first frames…".
   - [ ] Within 90s total, the card flashes "Streaming smooth to TV" and auto-hides.
7. [ ] Look at the TV:
   - [ ] Test stream plays smoothly at 60fps (the mux stream is 30fps source → RIFE doubles to 60).
   - [ ] No rebuffering during the first few minutes.
8. [ ] Check `~/.castbooster/cloud_state.json` — should have one pod entry with non-null `last_heartbeat` and `hls_url`.
9. [ ] Stop the cast (popup "Stop" button).
10. [ ] Check the pod was terminated:
    - [ ] RunPod web UI (`runpod.io/console/pods`) — the pod transitions to "Terminating" within 30s of stop.
    - [ ] `cloud_state.json` — pod entry removed.

If steps 1-10 all pass, Stage 1 succeeded.

### Stage 2 — Egydead (cookies)

This is the real product acceptance: Abed's daily-use platform.

1. [ ] In the same Chrome session, navigate to egydead.example (or whichever URL works today).
2. [ ] Load an episode. The extension's content script auto-captures cookies; verify in DevTools that the StreamSession is registered with cookies (`chrome.runtime` message bus).
3. [ ] Click "Cast" with smooth-motion ON.
4. [ ] Watch the popup warmup card — should follow the same progression as Stage 1.
5. [ ] Look at the TV:
   - [ ] Episode plays smoothly at 60fps.
   - [ ] No rebuffering past the warmup.
   - [ ] Audio is in sync with video.
6. [ ] Let it run for 5 minutes minimum.
7. [ ] Stop the cast.
8. [ ] Pod terminates within 30s (RunPod web UI).

If Stage 2 passes, Pillar 3.6 MVP product acceptance = DONE.

## Acceptance criteria (12 total)

From the amendments doc § "Acceptance updates":

v0.3.0 deferred (6):
- [ ] (1) `/process` returns 200 with hls_url within 1s. Verify via `~/.castbooster/cloud_state.json` getting populated immediately after pod boot.
- [ ] (2) `/process_status` flips `playlist_ready=true` within 90s. Verify via popup card transition from "Compiling engine…" to "Streaming smooth to TV".
- [ ] (3) `playlist.m3u8` shows multiple `#EXTINF:4.0xx,` lines (NOT one giant segment). Verify by curling `<pod-url>/hls/playlist.m3u8` mid-cast and inspecting.

- [ ] (5) `/process_status` reports `state="completed"` when source EOS reached. Verify by letting Stage 1's test stream play to its end.
- [ ] (6) `n_segments` plateaus at ~6 during steady-state RUNNING (rolling window). Verify by curl-polling `/process_status` across 30s of cast.

v0.3.1 source-proxy (3):
- [ ] (7) `POST /process` with `source_headers={"Cookie": "x"}` returns 200 (not 400). Verified implicitly by Stage 2 succeeding.
- [ ] (8) `bs.VideoSource` inside the pod reads from `http://127.0.0.1:8001/source_proxy?token=X` and successfully demuxes the first frame. Verify via pod logs: `docker logs <container>` should show `[run_rife] clip built: N frames @ ... fps`.
- [ ] (9) Egydead URL plays end-to-end through the cloud pipeline and lands on the TV. Verified by Stage 2 step 5.

Product acceptance (3):
- [ ] (10) 60fps visible on the TV (motion is visibly smoother than 30fps source — pan shots are the clearest test).
- [ ] (11) No buffering past the initial 90s warmup.
- [ ] (12) Popup warmup card shows the right progression in real time.

## Failure-mode triage

If any acceptance criterion fails, do NOT randomly try fixes — follow systematic-debugging. Common modes from prior gotchas:

### Pod stays `desiredStatus=RUNNING + currentStatus=None + runtime={}` for >5min

Phantom pod (decision doc `2026-05-28-v0.3.0-shipped-pod-verify-deferred.md`). Terminate, switch to a different GPU type in `CLOUD_GPU_TYPES` priority list, retry. Don't burn the full 6min boot timeout watching nothing happen.

### `/healthz` 200 but `/process` returns Cloudflare 502 with 15-byte body

The v0.1.x trap. v0.3.0 fixed it but if it reappears, the pod might have rolled back to a stale image. Verify `CLOUD_WORKER_IMAGE` is pinned to `v0.3.1` (NOT `:latest`).

### popup warmup card stuck on "Compiling engine + first frames…" past 90s

TRT engine cold-start is exceeding 90s budget. Options:
1. Wait up to 3min — the cold-start can be slow on a fresh node (engine bake step).
2. If it consistently exceeds 90s on cold pods, set `CLOUD_PLAYLIST_READY_TIMEOUT_S=180` in `.env` and retry.
3. Phase 2 fix: warm-pool a pre-baked engine. Out of MVP scope.

### Cast plays in VLC but Chromecast spins forever

Codec/container issue. NVENC outputs H.264 main profile by default. Verify pod logs: `ffmpeg ... -profile:v` — should NOT be `high`. Chromecast Gen 1 maxes at main profile.

### Egydead cookies not reaching the pod

Verify Stage 2 step 5 actually played. If 401/403 in pod logs from upstream fetch:
1. Check the extension's content script is still capturing cookies (re-login on egydead, retry).
2. Verify the StreamSession's cookies list has entries: `chrome.devtools` → `chrome.runtime.sendMessage({type: "ping"})`.
3. v0.3.1 source-proxy: tail pod logs for `/source_proxy` GET requests; each should show the registered Cookie header in the outgoing request.

### Pod doesn't terminate on cast stop

The proxy's `_on_session_end` callback should call `orchestrator.terminate_pod`. If it doesn't fire:
1. The cloud worker's own 10min `idle_watcher` should kill the pod after 10min of HLS dir inactivity — wait 12min, recheck RunPod web UI.
2. If 12min later still running: manually terminate via RunPod web UI. File a bug in master gotchas.

## What this runbook does NOT cover

- Polar.sh paywall (Pillar 6 — Pro license is currently stubbed/env-set).
- Multiple parallel casts (one pod = one cast for MVP).
- Cross-device cast (same Chromecast, different laptop).
- Anime4K upscale (Pillar 4).
- DRM-protected sources (Crunchyroll, Netflix — needs Widevine path, out of scope).
